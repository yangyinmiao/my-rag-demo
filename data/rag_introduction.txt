RAG 技术简介

RAG（Retrieval-Augmented Generation，检索增强生成）是一种将信息检索与大语言模型（LLM）相结合的技术框架。它于2020年由 Meta AI 研究团队在论文《Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks》中首次提出。

RAG 解决的核心问题

大语言模型虽然具备强大的语言理解和生成能力，但存在以下局限性：

1. 知识截止问题：LLM 的训练数据有时间限制，无法获取最新信息
2. 幻觉问题：LLM 可能生成看似合理但实际错误的内容
3. 领域知识不足：LLM 对特定垂直领域的专业知识了解有限
4. 无法引用来源：LLM 无法追溯其回答的信息来源

RAG 通过为 LLM 提供可靠的外部知识来解决这些问题。

RAG 的工作原理

RAG 系统包含两个主要阶段：

一、知识库构建阶段（离线）
1. 文档加载：收集并加载各种格式的文档（PDF、TXT、HTML 等）
2. 文本分割：将长文档切分为适合处理的小块（chunk），通常为 200-1000 个字符
3. 向量嵌入：使用嵌入模型（Embedding Model）将每个文本块转换为向量表示
4. 向量存储：将向量和对应文本存入向量数据库（如 ChromaDB、Faiss、Pinecone 等）

二、问答阶段（在线）
1. 问题理解：将用户的问题转换为查询向量
2. 相似度检索：在向量数据库中找出与问题最相似的 Top-K 个文档块
3. 上下文构建：将检索到的文档块拼接为上下文（Context）
4. 生成答案：将问题和上下文一起发送给 LLM，让其基于上下文生成答案

RAG 的核心技术组件

嵌入模型（Embedding Model）
嵌入模型负责将文本转换为稠密向量，是 RAG 检索质量的关键。常用模型包括：
- OpenAI text-embedding-3-small/large
- BGE（BAAI 通用嵌入）系列
- nomic-embed-text（支持 Ollama 本地部署）

向量数据库（Vector Database）
向量数据库专门用于存储和检索高维向量。主要类型：
- ChromaDB：轻量级，适合本地开发和学习
- Faiss：Facebook 开源，高性能，适合大规模数据
- Pinecone：全托管云服务，适合生产环境
- Milvus：开源分布式向量数据库，适合企业级应用

文本分割策略
分割策略直接影响检索质量：
- 固定大小分割：按字符数切分，简单但可能破坏语义
- 递归字符分割：按段落、句子、词语层次分割，保持语义完整性
- 语义分割：基于语义相似度分割，效果最好但计算开销大

RAG 的优化方向

基础 RAG 的常见问题及优化方案：

1. 检索质量不足
   - 混合检索：结合向量检索和关键词检索（BM25）
   - 查询改写：对用户问题进行改写或扩展
   - 重排序（Reranking）：对初步检索结果二次排序

2. 上下文窗口限制
   - 压缩上下文：过滤掉不相关的句子
   - Map-Reduce：分段处理后合并

3. 幻觉问题
   - 引用验证：要求 LLM 标注引用来源
   - 自我反思：让 LLM 检验自己的答案

RAG 的应用场景

RAG 广泛应用于：
- 企业知识库问答系统
- 法律文件分析与检索
- 医疗文献查询
- 客服自动化
- 代码文档问答
- 学术论文检索与问答

RAG 与微调的对比

微调（Fine-tuning）是另一种增强 LLM 能力的方式，两者对比：
- RAG 优势：无需重新训练模型，知识可实时更新，成本低，可追溯来源
- 微调优势：知识融入模型权重，推理速度更快，适合改变模型行为风格
- 实践建议：通常先用 RAG，若效果不满足需求再考虑微调
